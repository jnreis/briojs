Component specification:
- a registered component is JavaScript function that returns a JavaScript object
  - if any property of the object that is not a function is used in the component template, it will become reactive
- A DOM element is a component if:
  - it has a `component` attribute
  - the value of the attribute:
    - matches the name of a registered component
    - or can be evaluated to a JavaScript object
    - or to a function that returns a JavaScript object

Features:
- Element node
  - attribute binding
    - Examples: 
      - `placeholder="{reactiveData}"` // reactive
      - `placeholder="{derivedData}"` // reactive
      - `placeholder="{someMethod}"` // once
      - `placeholder="{someMethod('a', reactiveData)}"` // once
      - `placeholder="{1 + 1}"` // once
      - `placeholder="{count++}"` // once
      - `placeholder="{any js expression}"` // once
      - Note: Only reactive data and derived data will be updated when changed.
              Other expressions will be evaluated only once.
  - input two-way data binding
    - Examples:
      - `value="{reactiveData}"`
      - `checked="{reactiveData}"`
      - `selected="{reactiveData}"`
      - Note: Only reactive data can be used in two-way data binding.
              Two-way data binding registers an `input` event listener to update the reactive data when the input value changes and a data subscription to update the input value when the reactive data changes.
  - event listeners. Attributes with `on-` prefix.
    - `on-click="{someMethod}"`
    - `on-click="{event => someMethod(event, reactiveData, 'a')}"`
    - `on-click="{count++}"`
    - `on-click="{count = count + 1}"`
- Text node & Comment node
  - text binding
    - Examples:
      - `{reactiveData}`
      - `{derivedData}`
      - `{someMethod('a', reactiveData)}`
      - `{1 + 1}`
      - `{any js expression}`
      - Note: Only reactive data and derived data will be updated when changed.
              Other expressions will be evaluated only once.

Modules:
- render: 
  - responsible for retrieving from, parsing and hydrating top-level components back to the DOM.
  - the render is an array containing top-level components.
  - the array is an intance of the state module.
  - every virtual node in the render array is represented by an object that contains the following properties:
    - context: an object containing every reactive data, derived data, and method of the component. The context of every parent components is merged into the context of the child component like so `Object.assign({}, parentContext, childContext)`.
    - type: the type of the node (element, text or comment)
    - node: a DOM node (element, text or comment)
    - props: an object containing the node attributes and special properties of the node (e.g. component, show, if, each, on-click, etc.)
      - The props hold the original value, which is used to (re)create subscriptions when the node is added to the DOM.
      - Special properties, and attributes that evaluate to a falsy value are not rendered as attributes in the DOM.
    - children: an array of virtual nodes or a string (in the case of text and comment nodes)
    - subscriptions: every subscription created during the hydration of the node. The subscriptions are the backbone of the reactivity system.
      - The subscriptions are used to unsubscribe from the events when the node is removed from the DOM.
      - There are 3 types of subscriptions:
        - data subscriptions: subscriptions to an event in a path in the state object
        - derived subscriptions: subscriptions derived from data subscriptions (one or more data subscriptions)
        - event subscriptions: subscriptions to an event in a DOM node
- state:
  - a function that takes an initial value and keep track of subscriptions
  - the initial value is stored in the value property of the state object
  - the state object exposes the following methods:
    - get: returns a value in the state object
      - path: a string that represents the path to a property in the state object
    - set: sets a value in the state object
      - path: a string that represents the path to a property in the state object
      - value: the value to be set
    - on: subscribes to an event in a path in the state object
      - event: the name of the event (beforeCreate, created, beforeUpdate, updated, beforeDelete, deleted)
      - path: a string that represents the path to a property in the state object
      - callback: a function that is called when the event is triggered in the path
      - Note: the on method returns a function that can be used to unsubscribe from the event in the path
  - Notes:
    - an event can be registered in any path. Even if the path does not exist.
    - multiple callbacks can be registered for the same event in the same path, but not the same callback.
    - the callbacks are called in the order they were registered.
    - the callbacks are called with the following arguments (as an object):
      - value: the value of the path
      - path: the path
      - state: the state object, that contains the value property
    - the callbacks are called in the following situations:
      - beforeCreate: right before a path that is `undefined` is about to receive a value that is not `undefined`
      - created: when a path that was `undefined` receives a value that is not `undefined`
      - beforeUpdate: right before a path that holds a value that is not `undefined` is about to receive a new value that is not `undefined`
      - updated: when a path that holds a value that is not `undefined` receives a new value that is not `undefined`
      - beforeDelete: right before a path that holds a value that is not `undefined` is about to receive a value that is `undefined`
      - deleted: when a path that holds a value that is not `undefined` receives a value that is `undefined`
    - the beforeUpdate, updated, beforeDelete and deleted events bubble down to the subpaths of the path that triggered the event.
      - only the affected subpaths are triggered.
        - Example:
          - if the path `a.b` sets a new object that contains the properties `c.d` and there is a listener for the path `a.b.c.d` and `a.b.c.e`, only the listener for `a.b.c.d` will be notified for the event in question.
          - this is how the state function handles reactivity and keeps every listener notified of relevant changes, no matter how deep the path is.
- evaluate:
  - a function that takes a string and evaluates it in the context of the component
  - it may be a reactive data, derived data, method or any JavaScript expression
  - it returns the value of the expression
  - it is used to evaluate expressions in attributes and text nodes
