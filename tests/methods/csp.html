Strict CSP build

This page sends script-src 'self', so the browser blocks inline scripts and eval. It loads brio.csp.min.js, and its setup lives in csp.js. Only component templates from that file are hydrated; the page markup itself stays inert.

1. The policy is active

The page tries new Function() once to prove the policy works. That probe should be the only eval violation; Brio adds none.

2. Components defined in JavaScript work as usual

Static attributes become props (start is declared as a Number). The templates use template literals, events, b-model, b-for, b-if, and b-bind-class.

3. Page markup stays inert

None of this runs: not the text, the directives, nor the b-* attributes on a component host. The host still mounts, with only its static label.

4. Listen to page components from JavaScript

Because b-on-* is ignored on page hosts, csp.js listens to the counters' change events with addEventListener. Click a counter above.

5. Inserted markup is untrusted too

app.insert() treats its HTML like page markup: the registered counter mounts, and everything else stays raw.

Nothing inserted yet.

6. Templates must come from JavaScript

An #id selector or a <template> element would read page markup, so app.component() rejects them.
